Text Generation Web UI

The Text Generation Web UI is a Gradio-based interface for running Large Language Models like LLaMA, llama.cpp, GPT-J, Pythia, OPT, and GALACTICA. It provides a user-friendly interface to interact with these models and generate text, with features such as model switching, notebook mode, chat mode, and more. The project aims to become the go-to web UI for text generation and is similar to AUTOMATIC1111/stable-diffusion-webui in terms of functionality.

Features

  • Dropdown menu for switching between models
  • Notebook mode that resembles OpenAI's playground
  • Chat mode for conversation and role-playing
  • Instruct mode compatible with various formats, including Alpaca, Vicuna, Open Assistant, Dolly, Koala, ChatGLM, and MOSS
  • Nice HTML output for GPT-4chan
  • Markdown output for GALACTICA, including LaTeX rendering
  • Custom chat characters
  • Advanced chat features (send images, get audio responses with TTS)
  • Efficient text streaming
  • Parameter presets
  • Layers splitting across GPU(s), CPU, and disk
  • CPU mode
  • and much more!

Installation

There are different installation methods available, including one-click installers for Windows, Linux, and macOS, as well as manual installation using Conda. Detailed installation instructions can be found in the Text Generation Web UI repository.

Downloading Models

Models should be placed inside the models folder. You can download models from Hugging Face, such as Pythia, OPT, GALACTICA, and GPT-J 6B. Use the download-model.py script to automatically download a model from Hugging Face.

Starting the Web UI

After installing the necessary dependencies and downloading the models, you can start the web UI by running the server.py script. The web UI can be accessed at http://localhost:7860/?__theme=dark. You can customize the interface and behavior using various command-line flags.

System Requirements

Check the wiki for examples of VRAM and RAM usage in both GPU and CPU mode.

Contributing

Pull requests, suggestions, and issue reports are welcome. Before reporting a bug, make sure you have followed the installation instructions provided and searched for existing issues.

Voice-First Field Inspection Assistant

Field technicians often complete paperwork after leaving the equipment site. This creates extra administrative work, increases the chance of missing important details, and delays action on safety-critical problems. FieldMate lets technicians document inspections by speaking naturally while they work. AssemblyAI transcribes the technician’s voice in real time. FieldMate then converts each completed observation into a structured finding containing the affected equipment, severity, recommended action, and required parts. Technicians can use natural voice commands to mark an issue as critical, correct a previous finding, add a replacement part, create a follow-up task, or complete the inspection. Critical findings immediately trigger a visible safety warning. When the inspection is complete, FieldMate calculates the overall status and creates a reviewable professional PDF report. Completed and in-progress inspections are stored in Supabase, providing a history of job IDs, equipment context, findings, tasks, recordings, status, and safety flags. The application also supports typed observations when microphone access or real-time transcription is unavailable. A deterministic local parser provides an additional fallback if AI extraction cannot be reached. FieldMate helps technicians capture accurate information while details are fresh and gives maintenance teams faster access to actionable findings.

PlantAI:Plant Disease Diagnosis

PlantAI is an agentic computer vision system designed to help farmers, agricultural students, researchers, and plant-care professionals identify plant diseases quickly and make more informed decisions. Plant disease diagnosis is often dependent on manual inspection or expert knowledge, which can be slow, subjective, and difficult to access—especially when symptoms look similar across different diseases. A wrong or uncertain diagnosis can lead to inappropriate treatment, crop loss, and unnecessary use of pesticides. PlantAI addresses this problem through an AI-powered diagnosis pipeline that combines computer vision with agentic evidence verification. Users interact with a simple interface by uploading an image of a plant leaf. The computer vision model analyzes the image and predicts the most likely disease. Instead of relying only on a single classification result, PlantAI uses an ensemble of deep learning models to improve prediction reliability. The system combines EfficientNetV2-S, ConvNeXt-Tiny, and Swin-Tiny through weighted ensemble learning. A supervisor agent then coordinates additional evidence-gathering steps, including retrieval-augmented generation (RAG), disease-specific knowledge retrieval, web research, and contextual information. The collected evidence is analyzed and fused with the computer vision prediction to provide a more explainable and reliable diagnosis. A key feature of PlantAI is its focus on evidence-backed AI rather than simply returning a disease label. The system can provide the predicted disease, confidence information, supporting evidence, and relevant diagnostic context. When the available evidence is insufficient or the prediction is uncertain, the architecture can support uncertainty handling and abstention rather than forcing an unreliable answer. What makes PlantAI unique is the combination of high-performance computer vision, ensemble learning, RAG, web research, and agentic verification in a single plant-disease diagnosis workflow. This creates a multi-stage system where visual recognition is supported by external evidence and reasoning rather than operating as an isolated image classifier. The target users can upload a plant image through the web application and receive an AI-generated diagnostic response in an accessible, conversational format. PlantAI is designed to make advanced AI-assisted plant disease analysis more accessible while providing a foundation for future agricultural decision-support applications. PlantAI demonstrates how computer vision and agentic AI can work together to transform image-based disease recognition into a more evidence-aware and reliable diagnostic workflow.

Dev-Lens

Problem: Developers spend hours translating codebase realities for non-technical stakeholders. When product managers ask "How hard is this feature?" or clients ask "Why is this refactor necessary?", developers must pause their core work, inspect multiple repositories, evaluate architectural impact, and translate complex technical nuances into language suited for specific audiences (PMs, clients, managers, or support). Existing AI coding tools either write code or produce generic summaries prone to hallucinations that lack grounded architectural validation. Solution: I built DevLens, a developer-first codebase intelligence tool that bridges the gap between a developer’s mental model and stakeholder questions. By combining multi-repository indexing, a personalized "Developer Lens", and dual-engine AI validation powered by IBM Granite, DevLens delivers structured, 7-section technical impact analyses (Current System, What Would Change, Affected Areas, Effort, Risks, Unknowns, and Internal Developer Reasoning) tailored to any selected audience. Target Users: Software engineers, tech leads, engineering managers, and technical product managers working with single repositories or multi-service microservices. How Users Interact With It: 1. Context & Component Indexing: Users connect GitHub repositories or multi-service projects, allowing DevLens to index file trees, dependencies, and architectural components. 2. Define the Developer Lens: Engineers configure their investigation methodology (e.g., test-driven, data-flow first) and communication preferences (bullet points, trade-off focus), creating a reusable mental model that can be published as a public share link. 3. Audience-Aware Analysis: Users ask any engineering question and select their audience (Developer, PM, Manager, Client, or Support). DevLens generates a structured, role-adapted breakdown. 4. Granite Evidence Validation: IBM Granite automatically audits the analysis against indexed codebase evidence, categorizing claims (SUPPORTED, WEAKLY_SUPPORTED, CONTRADICTED) and surfacing architectural anomalies. 5. Report Bot: Users curate multiple saved analyses into a paginated, print-ready PDF engineering report via Paprize. What Makes It Creative & Unique: - Dual-Engine Trust: Unlike single-prompt LLM wrappers, DevLens separates generation from verification. IBM Granite acts as an objective validator to ensure claims reflect actual code. - Developer Lens Personalization: DevLens explains systems the way you think, preserving individual engineering insights across team handoffs. - Multi-Audience Pitching: The exact same architectural change is automatically translated into executive summaries for management, sprint impact for PMs, or line-level reasoning for developers. Effectiveness & Efficiency: DevLens eliminates hours of manual drafting, cross-team misunderstandings, and unverified architectural assumptions. Running on a lightweight Cloudflare Worker with D1 SQLite persistence and non-blocking IBM Granite inference, DevLens provides instant, verified engineering intelligence with zero infrastructure overhead.

VoiceOps AI - Conversational Voice to Action

VoiceOps AI bridges conversational speech and deterministic enterprise workflows. Built with Google's Gemini 3.8 Live API and Firebase Firestore, VoiceOps AI transforms free-form spoken voice into structured, verified operational actions with sub-500ms latency. Key Capabilities: 1. Gemini 3.8 Live Conversational Engine: Leverages real-time audio reasoning to understand complex customer requests, detect operational intent, and manage multi-turn dialogs. 2. Low-Latency Voice Turn-Taking & Barge-in: Implements Web Audio API frequency analysis, neural voice activity detection (VAD), and instantaneous barge-in interruption so callers can change their mind mid-sentence without robotic lag. 3. Deterministic Tool Execution & Verification: Binds natural voice commands to strict JSON schema tools (check_availability, create_booking, cancel_booking, escalate_to_human, and knowledge search). Every action is verified with reference IDs before verbal confirmation. 4. Firebase Firestore Persistence & Auth: Provides Google Sign-In with real-time Firestore synchronization. All conversation transcripts, appointment bookings, and executed dispatch actions are securely persisted under authenticated user profiles. 5. Real-Time Operations Pipeline: Visualizes speech input, intent detection, tool routing, dispatch execution, and verbal confirmation in an intuitive reactive dashboard. VoiceOps AI eliminates hold times, automates field scheduling, and empowers businesses to handle customer calls 24/7 with human-level naturalness and machine precision.

Auto Business Builder: Voice to Startup Kit

Starting a business shouldn't require a designer, a copywriter and a week of setup. Auto Business Builder turns a spoken idea into a launch-ready business kit in minutes. How it works: you pitch your idea by recording your voice in the browser (or uploading an audio file). AssemblyAI transcribes the speech with high accuracy, and you can review or edit the text before building. Gemini then analyses the pitch and generates a complete kit: a business name and tagline, a full landing page (hero, features, how it works, testimonials, pricing, call-to-action and a Book a Call button), three welcome emails, CRM pipeline stages, and realistic early-stage risk flags. Everything is saved and downloadable. The standout feature is the built-in AI website editor. Open the generated landing page in a new tab and you get a Replit-style split view: a chat panel on the left and a live preview on the right. Type requests like "change the hero to dark purple" or "add a pricing section" and Gemini rewrites the page instantly, replies with a short summary of what changed, and supports one-word undo. Failed AI calls are retried silently so users never see raw errors. Built with Python, Flask, AssemblyAI and the Gemini API, it helps solo founders go from idea to a presentable brand and website in one sitting.
